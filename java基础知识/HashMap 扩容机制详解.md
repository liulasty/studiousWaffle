`HashMap` 是 Java 中最常用的哈希表实现，其扩容机制直接影响性能。以下是 `HashMap` 扩容的核心原理和过程：

---

## **1. 扩容触发条件**
`HashMap` 在以下两种情况下会触发扩容（`resize()`）：
1. **元素数量超过阈值（`threshold`）**  
   - 默认阈值 = **容量（`capacity`） × 负载因子（`loadFactor`）**  
   - 默认容量 = **16**，默认负载因子 = **0.75**，因此首次扩容阈值为 `16 * 0.75 = 12`。  
   - 当元素数量（`size`）超过 `threshold` 时，触发扩容。

2. **链表长度过长（JDK 8 优化）**  
   - 在 JDK 8 中，当链表长度 ≥ **8** 且数组长度 ≥ **64** 时，链表会转为红黑树（优化查询效率）。  
   - 但如果数组长度 < 64，即使链表长度 ≥ 8，也会优先扩容（而非树化），以减少哈希冲突。

---

## **2. 扩容过程**
`HashMap` 扩容的核心步骤：
### **（1）计算新容量**
- **新容量 = 旧容量 × 2**（即每次扩容为原来的 **2 倍**，保证容量始终是 **2 的幂次方**）。
- 最大容量为 **2³⁰**（`1 << 30`），超过则不再扩容。

### **（2）重新计算哈希 & 迁移数据**
- 遍历旧数组的每个桶（`bucket`），重新计算每个键值对的哈希值，并分配到新数组的对应位置。
- **JDK 7**：使用头插法（可能导致死链，多线程不安全）。  
- **JDK 8**：使用尾插法（避免死链），并优化了哈希计算方式：
  - 如果键的哈希值高位不同，扩容后位置可能为 **原位置 + 旧容量**（利用 `(e.hash & oldCap) == 0` 判断）。

### **（3）更新阈值**
- 新阈值 = 新容量 × 负载因子（默认仍为 0.75）。

---

## **3. 扩容优化（JDK 8）**
JDK 8 对 `HashMap` 扩容做了以下优化：
1. **高位哈希判断**  
   - 通过 `(e.hash & oldCap) == 0` 判断元素在新数组中的位置：
     - 若为 `0`，则位置不变（`index = oldIndex`）。  
     - 若不为 `0`，则新位置 = `oldIndex + oldCap`。  
   - 避免了重新计算哈希，提升性能。

2. **链表拆分优化**  
   - 扩容时，链表会被拆分为 **低位链表**（留在原位置）和 **高位链表**（移动到 `原位置 + oldCap`）。  
   - 示例：
     ```java
     // 旧容量 = 16（二进制 10000）
     if ((e.hash & 16) == 0) {
         // 留在原位置（如 index=3）
     } else {
         // 移动到 index=3+16=19
     }
     ```

---

## **4. 扩容示例**
假设初始容量 = 16，负载因子 = 0.75，插入第 13 个元素时触发扩容：
1. **旧数组**：容量 = 16，阈值 = 12。  
2. **新数组**：容量 = 32（16 × 2），阈值 = 24（32 × 0.75）。  
3. **数据迁移**：
   - 遍历旧数组，重新分配键值对到新数组（利用高位哈希优化）。

---

## **5. 扩容对性能的影响**
- **时间复杂度**：扩容是 **O (n)** 操作（需遍历所有元素）。  
- **优化建议**：
  - 如果已知数据量较大，可提前指定初始容量（如 `new HashMap(1000)`），减少扩容次数。  
  - 避免频繁扩容（尤其是大容量 `HashMap`）。

---

## **6. 总结**
| **关键点**          | **说明**                                                                 |
|---------------------|-------------------------------------------------------------------------|
| 触发条件            | 元素数量 > `capacity * loadFactor` 或链表长度 ≥ 8（且数组长度 < 64）。 |
| 新容量              | 旧容量 × 2（最大 2³⁰）。                                               |
| 数据迁移优化（JDK 8）| 利用高位哈希判断，避免重新计算 `hash`。                                |
| 线程安全性          | 非线程安全，多线程扩容可能导致死链（JDK 7）或数据丢失（JDK 8）。         |

**最佳实践**：预估数据量，初始化时设置合适的容量（如 `new HashMap(预期大小 / 0.75 + 1)`）。
